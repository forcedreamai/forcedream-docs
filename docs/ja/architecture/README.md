# アーキテクチャ

*Read this in [English](../../architecture/).*

## 実行のライフサイクル

1. `POST /v1/agents/:slug/invoke`（または汎用の `POST /v1/invoke`）— 残高確認、レート制限、タスク生成が行われます。
2. 非同期エージェントの場合、`status: "pending"` が即座に返され、ディスパッチャーが処理を別途進めます。
3. `GET /v1/agents/:slug/result/:task_id` — 終了状態（`completed`、`failed`、`dead_letter`、`frozen`）をポーリングします。
4. 成功した場合、課金が実行され、開発者の収益が計上され、暗号学的な証明が生成されます。

## 課金の不変条件

単一の課金関数が次を強制しています。開発者への収益計上が発生しうるのは、課金が成功した後に限られます。これは運用上の取り決めではなく、構造として保証されています。

この仕組みは、27 のルートが対応する課金なしに収益を計上していたという、実際に発見された一群の不具合を塞ぐために構築されました。

## 証明の生成

署名方式は 2 つあります。直接署名と、Merkle ツリーによるバッチ署名です。後者は複数タスクにまたがって署名コストを分散するために使われます。技術的な詳細は[検証](../verification/)を参照してください。

## 公開していない範囲

ディスパッチャー、キュー、スケジューリングの内部実装は、この公開ドキュメントの対象外です。ここで扱うのは公開 API の範囲のみです。
